# RB Banner Maker — Netlify version

This is a static Vite website with Netlify Identity account authentication and a protected Netlify Function for admin account management. Public sign-up is intended to stay enabled.

## Deploy to Netlify

1. Upload this project to a Git repository (GitHub, GitLab, or another supported provider) and connect that repository from <https://app.netlify.com/>. This project includes serverless Functions, so deploy it through a Git-connected Netlify build or Netlify CLI rather than relying on a static-only drag-and-drop deployment.
2. Build settings are in `netlify.toml`: build command `npm run build`, publish directory `dist`, functions directory `netlify/functions`.
3. In the Netlify project dashboard, open **Project configuration → Identity** and enable Identity.
4. Under **Identity → Registration**, set registration to **Open** so anyone can sign up. Keep email confirmation enabled for better account security.
5. Deploy the site over HTTPS. Open the live URL and create your own account.
6. In **Identity → Users**, open your own account, edit its roles, and add the exact role `admin`. Save, then sign out and sign in again so the updated role is reflected in your session.
7. Click the small `•••` button in the top-right corner and use your admin account to unlock the control desk.

## Features

- Public email/password sign-up, sign-in, and password recovery.
- Session restoration through Netlify Identity.
- Banner editor at `/maker.html`, with its CSS and JavaScript in separate source files under `src/`.
- A discreet top-right admin entry button. Admin rights are checked again inside the server function; hiding the button is not used as the security boundary.
- Admin can create users with a generated temporary password, reset a non-admin user's password, or revoke a non-admin account.
- Admin-created/reset accounts must change the temporary password at first login.
- Server-side audit log records account-management events without storing passwords.
- The credential log (including temporary passwords) is local to the admin's current browser profile and can be exported as CSV. Treat that log and exported files as sensitive; clear it on shared machines.

## Security notes

- No Identity operator token or other admin secret is embedded in the browser bundle.
- The admin function checks the authenticated user's `admin` role server-side and validates the request origin for writes.
- The banner editor's JavaScript/CSS are client-side assets and can be inspected by visitors who have access to the site. Do not put secrets or private data in those files. Admin operations and sensitive credentials are handled separately by the server function.
- The password generated by the admin function is returned to the admin once and not stored in the server audit log. A local copy is kept in browser storage only because the requested workflow includes a credential log. Use it only from a private admin machine.
- Identity role changes normally take effect after the user signs in again or refreshes their session.

## Local development

Install a current Node.js LTS release, then run:

```sh
npm install
npm run build
```

For Netlify Identity / Functions testing, deploy to a Netlify Deploy Preview. A plain local static preview cannot exercise the production Identity endpoints or admin operator token.
